# Mina App - Current State and Future Plans

## Current Implementation

### Data Layer
1. Database Schema

   - day Table: Stores basic day information
     - id (INTEGER AutoIncrementing)
     - date (DateTime)
     - is_period_day (BOOLEAN)
     - note (TEXT)
     - symptom_list (TEXT)
     - mood_list (TEXT)
     - user_id (TEXT FOREIGN KEY referencing user.uuid)
   
   - period_day Table: Stores period-specific information
     - id (INTEGER AutoIncrementing)
     - date (DateTime)
     - flow_weight (INTEGER)
     - is_period_start_day (BOOLEAN)
     - is_period_end_day (BOOLEAN)
     - user_id (STRING)
     - day_id (INTEGER FOREIGN KEY referencing day.id)
  

   -cycle Table: Stores cycle-start, period-end and cycle-end dates
      - id (INTEGER AutoIncrementing)
      - start_date (DateTime)
      - period_end_date (DateTime)
      - end_date (DateTime)
      - user_id (STRING FOREIGN KEY referencing User.uuid) 

   -user Table: Stores user specfic information
      - id (INTEGER Auto-Incrementing)
      - created_at (DateTime)
      - user_id (TEXT)
      - name (TEXT)
      - surname (TEXT)
      - email (TEXT)
      - age (INTEGER)

   -note Table: Stores user notes
      - id (INTEGER Auto-Incrementing)
      - created_at (DateTime)
      - updated_at (DateTime),
      - title (TEXT),
      - content (TEXT),
      - user_id (STRING FOREIGN KEY referencing user.uuid),
   

2. Model Classes
   - Day: Base class for all day entries
   - PeriodDay: Inherits from Day, adds period-specific fields
   - MoodList: Manages mood tracking
   - SymptomList: Manages symptom tracking
   - Cycle: Represents a menstrual cycle
   - User: User class representing user profile.
   - PredictedDay: A day that inherits from PeriodDay class for days in the future. 

3. Repositories
   - DayEntryRepository: Handles Day and PeriodDay CRUD operations
   - CycleRepository: Manages cycle calculations and history
   - UserRepository: Manages the User settings.

   
### UI Layer
1. Views
   - DayEntryView: Form for entering day information
   - Dashboard: Main app interface (in progress)

### Architecture
- Using Bloc pattern for state management
- Repository pattern for data access
- Singleton pattern for database access
